## 32. How do you ensure your code is secure?

Great question! As a Full Stack Java Developer and Module Lead, ensuring **code security** is a critical responsibility—especially in production systems where **user data, APIs, and integrations** must be protected.

Here’s a structured, experience-backed answer:

---

### ✅ **Answer: How Do You Ensure Your Code is Secure?**

I follow a **multi-layered approach** to writing secure code—focusing on **secure coding practices, validation, proper authentication**, and **preventing known vulnerabilities** at every level of the stack.

---

### 🔐 **1. Input Validation & Sanitization**

- I always validate **user inputs on both client and server side**.
- I use frameworks like **Hibernate Validator** or **Spring’s `@Valid` annotations** to enforce strong input constraints.
- I sanitize inputs to prevent **injection attacks** (e.g., escaping special characters in SQL, HTML).

> ✅ Example: Preventing malicious `<script>` injection by sanitizing user-generated content.

---

### 🛡️ **2. Preventing SQL Injection**

- I **never use string concatenation** in queries.
- I use **prepared statements or parameterized queries** via Hibernate/JPA.
- For complex queries, I use named parameters and enforce **whitelisting of column names**.

> ✅ Example: `@Query("SELECT u FROM User u WHERE u.email = :email")` instead of raw query building.

---

### 🔑 **3. Authentication & Authorization**

- I integrate **Spring Security** to protect APIs and restrict access based on roles.
- I follow **Principle of Least Privilege (PoLP)** when assigning roles or scopes.
- I use **JWT (JSON Web Token)** or **OAuth2** for secure session management in stateless services.

> ✅ Example: APIs like `/admin/users` are accessible only to users with `ROLE_ADMIN`.

---

### 🔐 **4. Secure Password Handling**

- I use **BCrypt** to hash passwords before storing them.
- I enforce **strong password policies** and avoid storing any plain-text credentials.

---

### 🚫 **5. Protect Against Cross-Site Scripting (XSS)**

- I escape and encode outputs in the frontend (React) using libraries like **DOMPurify**.
- I avoid rendering raw HTML from user inputs unless absolutely necessary.

---

### 🔁 **6. CSRF Protection**

- For stateful apps, I enable **CSRF tokens** in Spring Security.
- In stateless apps (with JWT), I verify token signature and expiry with every request.

---

### 🧪 **7. Secure Error Handling & Logging**

- I avoid exposing sensitive stack traces or internal logic in API error responses.
- I log securely using tools like **Logback**, ensuring **PII masking** and **log rotation**.

---

### 📦 **8. Secure Dependencies**

- I regularly check for vulnerabilities using tools like:

  - **OWASP Dependency-Check**
  - **SonarQube with security rules**
  - **GitHub Dependabot alerts**

---

### 📄 **9. HTTPS & Secure Headers**

- I ensure APIs and frontends are served only over **HTTPS**.
- I configure secure HTTP headers like:

  - `X-Frame-Options: DENY`
  - `Content-Security-Policy`
  - `X-Content-Type-Options: nosniff`

---

### 🧯 **10. Static Code Analysis & Reviews**

- I use **SonarQube, SpotBugs, and Checkstyle** to catch vulnerabilities during development.
- During **code reviews**, I specifically check for:

  - Hardcoded secrets
  - Unsecured endpoints
  - Weak encryption
  - Overly permissive access

---

### 🔚 **Conclusion:**

To ensure security, I focus on writing **defensive code**, following **best practices**, and leveraging **tools** for early detection of risks. I also stay updated with **OWASP Top 10** vulnerabilities and apply mitigations as part of regular development.
