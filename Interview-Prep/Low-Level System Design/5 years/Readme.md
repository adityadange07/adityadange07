Here are the **Top 50 Low-Level System Design (LLD) Interview Questions** tailored for someone with **5 years of experience**. At this level, you're expected to **translate requirements into detailed class designs**, **write clean and extensible code structures**, and **think about object-oriented design principles**, **design patterns**, **code modularity**, and **interface design**.

---

## ✅ Top 50 Low-Level System Design Interview Questions (5 Years Experience)

---

### 🔹 1. Basics of Object-Oriented Design

1. **What are the SOLID principles? Can you explain each one with examples?**
2. **How do you apply design patterns in low-level design?**
3. **What is the difference between composition and inheritance?**
4. **What is an interface? Why is it important in LLD?**
5. **What are some anti-patterns in LLD you try to avoid?**

---

### 🔹 2. Design Principles & Best Practices

6. **How do you make your code extensible and maintainable?**
7. **What is dependency injection and why is it useful?**
8. **How do you handle validation logic in your design?**
9. **How do you ensure thread safety in your classes?**
10. **How would you implement logging in a modular way?**

---

### 🔹 3. Class Design Questions

11. **Design a class structure for a Parking Lot system.**
12. **Design an Elevator system in a multi-story building.**
13. **Design a Library Management System.**
14. **Design a Hotel Booking System.**
15. **Design a Movie Ticket Booking System.**

---

### 🔹 4. Code Modeling & Relationships

16. **How would you model "is-a" and "has-a" relationships in a class diagram?**
17. **What is aggregation vs composition? How would you use them?**
18. **What is polymorphism and how do you apply it in real designs?**
19. **Explain encapsulation with a real-world class design example.**
20. **What’s the difference between static and dynamic binding?**

---

### 🔹 5. Practical OOP Design Scenarios

21. **Design a Notification System (Email, SMS, Push).**
22. **Design a File System similar to Unix.**
23. **Design a Logging Framework.**
24. **Design a Splitwise-like Expense Sharing App.**
25. **Design a Ride Sharing System like Uber.**

### 🔹 6. Common Design Patterns

26. **When would you use the Strategy pattern?**
27. **Explain the Singleton pattern and how to implement it thread-safely.**
28. **What is the Observer pattern and where would you use it?**
29. **What is the Factory Method pattern? Give an example.**
30. **Explain the Decorator pattern with a real-world use case.**

---

### 🔹 7. Interface Design & Extensibility

31. **How would you design a pluggable payment system?**
32. **How do you separate concerns in a large class hierarchy?**
33. **How would you implement access control in a file system?**
34. **Design an Audit Trail mechanism in your system.**
35. **Design a modular reporting system that can generate PDFs and CSVs.**

---

### 🔹 8. Concurrency & Thread Safety

36. **How would you design a thread-safe counter class?**
37. **What are the common concurrency issues in low-level design?**
38. **How would you design a producer-consumer system?**
39. **How do you manage shared state across multiple threads?**
40. **What is double-checked locking and when would you use it?**

---

### 🔹 9. Design for Testing & Modularity

41. **How do you make your code testable during design?**
42. **How would you structure your code to allow mocking external dependencies?**
43. **How do you handle cross-cutting concerns like logging, auditing, etc.?**
44. **How do you design with interfaces and abstract classes for future growth?**
45. **What is inversion of control (IoC) and how do you apply it?**

---

### 🔹 10. Advanced Design Scenarios

46. **Design a Rate Limiter class (Token Bucket or Leaky Bucket).**
47. **Design a Cache with LRU eviction policy.**
48. **Design a Messaging Queue System (basic RabbitMQ-like).**
49. **Design a Thread Pool Executor.**
50. **Design an API Throttling mechanism.**

---

### 📘 Bonus Tip:

LLD rounds often come **after HLD** and are **code-focused** — be ready to write class diagrams, explain relationships (1:1, 1:N), apply design principles, and make real-time design decisions. Interviewers also **care about naming conventions, abstraction, reusability**, and **unit testability**.
